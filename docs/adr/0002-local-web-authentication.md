# ADR-0002: 本地 Web 鉴权与秘密轮换

- 状态：accepted
- 日期：2026-08-25

## 背景

只监听回环地址不能阻止同机恶意进程、浏览器扩展、DNS rebinding 或跨站请求调用控制
API。项目需要保护进程、配置、核心更新和代理通道等修改操作，同时保持单用户源码部署
简单可审计。

## 决策

1. 鉴权默认开启。首次启动生成 32 字节随机 token，保存到权限为 `0600` 的项目配置；
   操作者读取本机文件中的 token 完成首次登录，不提供未鉴权的远程配对端点。
2. 登录必须来自允许的 Host 和同源 Origin，token 使用常量时间比较。成功后签发 24 小时
   `HttpOnly`、`SameSite=Strict` Cookie；签名密钥只存在于当前 Web/API 进程内存中。
3. 除最小化的 `/healthz` 和登录入口外，API 与 SSE 均要求有效会话。所有非安全方法还
   必须通过 Origin 和 CSRF token 校验。
4. token 轮换采用运维操作：停止服务、修改 `0600` 配置文件、重新启动。进程重启同时
   更换会话签名密钥，使全部旧会话失效。
5. 只有显式配置 `web.enabled=false` 才允许关闭鉴权，并且 API 仍必须绑定明确的回环 IP。

## 影响

- 不需要用户数据库、恢复邮件、持久会话表或额外身份服务，符合本机单用户边界。
- token 不进入 URL、浏览器存储、日志或 SSE；浏览器只持有不可读的会话 Cookie。
- 当前模型不提供多用户、权限分级、在线 token 轮换或远程首次配对。若产品改为 LAN Web
  管理或公网管理，必须重新评审 TLS、Cookie `Secure`、登录限速和身份恢复机制。

## 已拒绝方案

- 仅依赖 localhost 而完全关闭认证。
- 把长期 token 放入 URL 查询参数或 `localStorage`。
- 让每个 handler 自行决定是否执行认证、Origin 或 CSRF 校验。
