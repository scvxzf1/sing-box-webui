# ADR-0004: 崩溃重启及退出语义

- 状态：accepted
- 日期：2026-08-25

## 决策

1. 同一 generation 和最后已验证配置路径最多自动重启 3 次。
2. 退避从 250 毫秒开始指数增长，上限 2 秒，并加入正负 20% 抖动。
3. 单次进程稳定运行 30 秒后重置重试计数，使偶发的长期运行后崩溃拥有新的恢复预算。
4. 用户主动停止关闭该 generation 的完成通道，从而取消等待中的重启计时器；旧
   generation 的计时器不得启动新进程。
5. 重试期间 supervisor 使用 `starting`，control service 保留系统代理。预算耗尽后才
   进入 `failed`，停止健康检查和连接监控、恢复系统代理并发布 `runtime.failed`。
6. Web/API 在最终失败后继续运行，供用户查看诊断或显式重新应用，不跟随核心退出。

## 影响

- 短暂核心崩溃不会立即把桌面系统代理切回直连；恢复成功后原运行目标继续有效。
- 连续崩溃不会形成无界循环，最终状态和错误仍可由 API 查询。
- 当前测试覆盖崩溃后成功重启、预算耗尽、退避期间主动停止、稳定窗口计数重置、
  重试期间保留系统代理，以及最终失败后的 control 清理，并通过 race detector。
- 重新 Apply 与退避计时器竞争仍应增加更精确的集成测试；这是实现覆盖缺口，不改变
  已接受的策略。

## 已拒绝方案

- 无限制自动重启或固定频率永久重试。
- 任意一次崩溃都立即恢复系统代理，从而在可恢复重启期间产生不必要的状态摆动。
- 核心最终失败时退出 Web/API，使用户失去本机诊断和显式恢复入口。
